# Security mechanisms, one row each

Point 97: a mechanism that cannot name its threat is decoration. Everything this system does
in the name of security or privacy is listed below with the six things that make it a
mechanism rather than a mood — what it is for, what it stops, the property it provides, where
it lives, what proves it works, and what happens when it fails. A row that cannot be filled in
is a feature to delete, not to ship.

`test/mechanisms.test.ts` reads this table: every row must have all six, the implementation
must be a file that exists, and the test must be a suite that exists.

| Mechanism | Threat | Security property | Implementation | Test | Failure mode |
| --- | --- | --- | --- | --- | --- |
| Client-side Argon2id, split into an auth secret and a vault key | A server or a database thief learning the password | The password never leaves the browser | `src/shared/crypto/vault.ts` | `test/cryptography.test.ts` | Weak parameters on an old device slow derivation; the server still never sees a password |
| scrypt over the auth secret, server-side | Offline guessing against a stolen `users` table | A stolen row costs work per guess | `src/server/lib/password.ts` | `test/auth.test.ts` | Parameters too low make guessing cheaper; the split above still stands between it and the password |
| X3DH handshake with signed and one-time prekeys | Passive recording, and a server substituting keys | Forward secrecy from the first message; keys are the user's | `src/shared/crypto/x3dh.ts` | `test/protocol.test.ts` | Prekey exhaustion falls back to the signed prekey, which is weaker but not broken |
| One-time prekey claimed by a single `DELETE … RETURNING` | Two callers racing for the same key on a database with real concurrency | A one-time key is handed to exactly one caller, on both drivers | `src/server/routes/keys.ts` | `test/security.test.ts` | A caller that loses the race retries three times, then answers with a bundle without a one-time key |
| Double ratchet with encrypted headers | A recorded session decrypted after a key compromise | Forward secrecy and post-compromise recovery | `src/shared/crypto/ratchet.ts` | `test/protocol.test.ts` | Desynchronisation makes a conversation unreadable; skipped keys expire rather than accumulate |
| Delivery timing noise | Correlating a send with the fetch that follows it, and fingerprinting a client by its polling cadence | Weakened timing correlation — explicitly not resistance to full traffic analysis, which needs cover traffic | `src/shared/jitter.ts` | `test/timing.test.ts` | A delayed envelope is late, never lost: `available_at` only gates the fetch, and the expiry sweep is unchanged |
| Sealed sender: single-use send tokens | An operator, or an order for records, asking which account sent an envelope | Sender unlinkability in data at rest — no stored row joins a message to an account | `src/server/lib/send_tokens.ts` | `test/sealed_sender.test.ts` | A refused or exhausted token falls back to an authenticated send: delivery continues with the visibility it had before, and never silently stops |
| Plaintext padding to fixed buckets | Length as a proxy for content | Sizes leak buckets, not messages | `src/shared/crypto/padding.ts` | `test/padding.test.ts` | Padding raises bandwidth; unpadding a corrupt frame fails closed |
| Sealed vault for private keys | A server or backup thief reading identity keys | Keys at rest are opaque to the server | `src/shared/crypto/vault.ts` | `test/recovery.test.ts` | A forgotten password and no recovery phrase means the vault stays sealed forever, by design |
| Safety numbers and per-device identity | A key substituted between two people | Man-in-the-middle is detectable out of band | `src/client/verification.ts` | `test/verification.test.ts` | Nobody compares them; the risk is unmitigated but visible in the interface |
| Recorded peer key history, and a banner when it changes (AUTH-6) | A released username registered by someone else, or a key substituted in a conversation nobody verified | An identity change is surfaced before the next message, without a server-side record of who left | `src/client/verification.ts` | `test/verification.test.ts` | The record is per device and per vault; a change that happens while this device is not in contact is only noticed on the next send or receive, and the banner can be dismissed without comparing anything |
| Final revocation of a device identity | A stolen device re-publishing itself | A revoked key never returns | `src/server/routes/keys.ts` | `test/security.test.ts` | An unrevoked stolen device keeps working until it is revoked |
| Session cookies: `HttpOnly`, `SameSite=Strict`, rotation and idle expiry | A stolen or long-lived session | A token is short-lived and not readable by script | `src/server/lib/sessions.ts` | `test/sessions.test.ts` | A cookie stolen from a live browser works until the next rotation or a sign-out everywhere |
| CSRF in three layers: `SameSite`, `Origin` check, double-submit token | A cross-site page acting as the user | Unsafe methods need a token no other origin can read | `src/server/security.ts` | `test/security.test.ts` | A browser that sends no `Origin` still faces the other two layers |
| Content-Security-Policy with Trusted Types | Injected script | The DOM cannot be built from a string | `src/server/security.ts` | `test/hardening.test.ts` | An old browser ignores Trusted Types; `el()` and the lint rule still forbid markup from strings |
| Role checks in the handler, with refusals audited | Privilege escalation, and a compromised staff account | Authorisation is proved per request, not rendered | `src/server/app.ts` | `test/authorization.test.ts` | A missing check on a new route is caught by the sweep over the route table |
| Per-operation token buckets, counted against the account | Brute force, scraping, spam | One operation cannot exhaust another, and one account cannot exhaust everyone | `src/server/lib/rate_limit.ts` | `test/limits.test.ts` | Limits too loose let abuse through; too tight and a real user is throttled, with `retryAfterSeconds` to say so |
| Proof of work on unauthenticated account endpoints | Bulk account creation and credential stuffing | Every attempt costs arithmetic, with no third party | `src/server/lib/pow.ts` | `test/antiautomation.test.ts` | A determined attacker pays the cost; a slow device waits longer to sign in |
| Validation and canonicalisation of every field | Injection, homoglyph and direction-override spoofing | What reaches SQL and the DOM is a known shape | `src/server/lib/validate.ts` | `test/security.test.ts` | An over-strict rule rejects a legitimate value, which is the direction that fails safely |
| Constraints and unique indexes in the schema | Races between two requests | The database refuses a state the application would not write | `src/server/db/migrations/007_integrity.sql` | `test/integrity.test.ts` | The loser of a race gets a 409 instead of a corrupt row |
| Blind blob storage for deliveries and attachments | A server or operator reading files | Bytes are stored without owner, name or type | `src/server/routes/deliveries.ts` | `test/attachments.test.ts` | Anyone holding an id can fetch the ciphertext; the key is still needed to open it |
| Free-space floor in front of blob writes | Disk exhaustion by uploads inside the rate limit | Writes stop before the database does | `src/server/lib/storage.ts` | `test/mechanisms.test.ts` | Uploads are refused with 503 while the disk is low; everything else keeps working |
| An object-count ceiling beside the free-space floor | A million tiny uploads, which cost little disk and a great deal of index, sweep and backup time | Blob rows are bounded by `MAX_BLOB_ROWS`, counted across both blob tables | `src/server/lib/storage.ts` | `test/jobs.test.ts` | The count is cached for 30 seconds, so the ceiling is approximate by a handful of rows; it refuses uploads with 503 and touches nothing else |
| A storage layer that stopped answering is a refusal, not a silent write | A data filesystem that has gone away while the service keeps accepting uploads into it | Repeated `statfs` failures on a path that used to answer refuse blob writes with 503 `storage_unavailable`, and say so on the health endpoint | `src/server/lib/storage.ts` | `test/mechanisms.test.ts` | A path that never answered is treated as a deployment where the check cannot run, so a Postgres host or a container without the data directory is never degraded by it |
| No access log, and one scrubbed line per fault | Retrospective surveillance from the server's own records | There is no history of who asked for what | `src/server/lib/log.ts` | `test/logging.test.ts` | Debugging is harder on purpose; a fault carries a reference, not a request |
| Aggregate-only metrics behind an administrator session | Monitoring becoming a time series of user behaviour | Counters hold numbers, not subjects | `src/server/lib/metrics.ts` | `test/observability.test.ts` | An operator who wants history has to build it, and is told what that costs |
| Encrypted backups with a retention window | A backup set becoming a permanent copy of deleted data | Snapshots expire and are verifiable | `scripts/backup.mjs` | `test/backup.test.ts` | A lost backup key makes restores impossible; the key is deliberately off the machine |
| Restore drill (`npm run backup:drill`) | A backup that decrypts but that the service cannot start on | Recoverability is demonstrated, not assumed | `scripts/backup.mjs` | `test/backup.test.ts` | The drill fails loudly and leaves the live database untouched; it is a copy on a random port |
| Reproducible build, SRI, published digests | A bundle targeted at one user | What is served can be compared with what was built | `scripts/build-client.mjs` | `test/deployment.test.ts` | A mismatch is visible only to someone who checks; `/build.txt` makes checking cheap |
| Network tiers with no egress from the application | SSRF, and a dependency phoning home | An outbound connection has nowhere to go | `deploy/docker-compose.yml` | `test/deployment.test.ts` | A container escape defeats it; that is stated as residual risk |
| Connection, timeout and statement ceilings | Resource exhaustion that never sends a request | The kernel queues instead of the process dying | `src/server/app.ts` | `test/resources.test.ts` | A cap set too low refuses legitimate traffic under a spike |
| Break-glass tooling that can only remove access | An operator with a shell during an incident | Emergency powers subtract, never read | `scripts/incident.mjs` | `test/incident.test.ts` | It cannot undo what it did; sessions must be re-established |
| Escrow-only guarantee, with the level and the catalogue behind it | A deal moved off the platform, where the buyer has no hold and no dispute | Standing and visibility come only from settled on-platform orders | `src/server/lib/reputation.ts` | `test/market.test.ts` | An incentive, not a rule: a determined pair still transacts elsewhere, and loses nothing but standing |
| Listing publishing rules | A public advertisement that offers a way around the escrow | A wallet address, an email address, another messenger or a "pay me directly" phrase does not publish | `src/server/lib/listing_policy.ts` | `test/market.test.ts` | Trivially evadable by anyone who wants to; it stops the offer being advertised, and it never touches the encrypted chat |
| Enforced deposit minimum, recorded not kept | Dust top-ups, and the accusation that a platform keeps them | A transfer under the floor is a visible uncredited row, refunded by hand | `src/server/lib/ledger.ts` | `test/wallet.test.ts` | The payer waits for a human; there is no automatic refund, because Monero names no sender |
| A view-only wallet beside the application | A spend key in the process that serves the internet | The web tier can see money arrive and has nothing that signs | `src/server/lib/monero.ts` | `test/monero.test.ts` | It can still hand out addresses and read what arrived; a compromise is a privacy loss, not a theft |
| One permanent subaddress per account | A payment nobody can attribute, or one credited to the wrong person | The index is the attribution, and it never changes | `src/server/lib/deposits.ts` | `test/monero.test.ts` | An operator who restores an older wallet file hands out indices that are already taken |
| Credit only at N confirmations, never from the pool | A top-up credited for a transaction that never lands | Money exists when the chain says so, not when the wallet first sees it | `src/server/lib/deposits.ts` | `test/monero.test.ts` | Six minutes of waiting for every payer, stated on the screen |
| A payout worker that pulls, on a host nothing can call | A compromised web tier ordering payouts to itself | The only process with a key has no inbound surface, and refuses above its float | `scripts/payout-worker.mjs` | `test/monero.test.ts` | A worker that dies mid-send leaves a payout an operator must resolve by hand; nothing retries automatically |
| Solvency compared on the watcher's clock | A shortfall discovered by a seller | Liabilities against the wallet's own total, with a loud line when they diverge | `src/server/lib/deposits.ts` | `test/monero.test.ts` | It says *that* the books and the wallet disagree, never why |
| A refund claims deposit rows before crediting them | The same dust refunded twice by two racing requests | One `UPDATE … RETURNING` decides who owns the money, and the loser is told there is nothing to refund | `src/server/lib/refunds.ts` | `test/refunds.test.ts` | An operator's manual refund and this route can still disagree about *which* rows, so operators mark rows, never just send |
| A floor under a refund, not a fee taken out of it | Dust top-ups used to drain the payout float through network fees | The platform pays the fee, so a refund must be worth more than one; under the floor it waits, visibly | `src/server/lib/refunds.ts` | `test/refunds.test.ts` | Money under the floor moves only when a human moves it, and the screen says exactly that |
| A level that decays with dormancy, reversibly | A catalogue sorted by who traded once, forever | One step per idle period off the *shown* level; the earned volume is untouched and one sale restores it | `src/server/lib/reputation.ts` | `test/standing.test.ts` | It cannot tell a seller on holiday from a seller who left; both fade, and both come back with one sale |
| A suspension costs a level that reinstatement does not return | An investigated account returning above sellers who traded honestly throughout | A penalty counter that only subtracts, earned back by crossing the next volume threshold | `src/server/lib/reputation.ts` | `test/standing.test.ts` | A mistaken suspension costs standing too; undoing it is deliberate SQL, not a button |
| A stuck payout is resolved by a human, with a receipt | An automatic retry paying a payee twice | `sending` is one-way; the only ways out are a transaction id an operator found, or an explicit "nothing left" | `src/server/routes/moderation.ts` | `test/monero.test.ts` | It trusts the operator's reading of their own wallet; a wrong "it never left" pays twice, and the dialog says so |
| Evidence committed as a keyed digest, never uploaded | A party changing their story about which file was sent | `HMAC-SHA256(order id, bytes)` published before the argument; the counterparty holds the file and can check | `src/server/lib/evidence.ts` | `test/evidence.test.ts` | It proves an order of events, not a fact: a digest says nothing about whether the file was good, or ever sent |
| Two administrators for a payout above a threshold | One stolen admin session releasing the float | Distinct rows in `withdrawal_approvals`; the quorum is checked in the same transaction that queues the payout | `src/server/lib/ledger.ts` | `test/wallet.test.ts` | It assumes two admins are not the same person; a deployment with one admin has to raise the threshold and know that it did |
| A network-level request cap in front of the application's buckets | An unauthenticated flood spending CPU before any per-account logic runs | An address-keyed cap at the reverse proxy, with per-account buckets behind it | `deploy/Caddyfile` | `test/deployment.test.ts` | Needs a Caddy plugin, and does nothing for onion traffic — every request there arrives from 127.0.0.1 |
| One confirmation for a small top-up, three for a large one, never zero | A six-minute wait on a 0.03 XMR purchase, and the zero-conf theft it tempts people into | One function decides the count per transfer; the floor is one confirmation at any amount | `src/server/lib/deposits.ts` | `test/monero.test.ts` | A one-block reorganisation can orphan a credited transfer: bounded by `FAST_CREDIT_MAX_XMR` per attempt |
| A signed prekey that rotates during a live session | A browser signed in for months protecting every new conversation with one week-old key | The server publishes staleness against the client's own constant; the browser rotates in the background | `src/client/state.ts` | `test/linking.test.ts` | A device nobody opens again keeps its last signed prekey until it is revoked — revocation, not rotation, is the answer to a lost phone |
| Background sweeps isolated from each other | One failing prune silently cancelling five others | Per-job `try`, per-job log line, ordered by importance | `src/server/lib/jobs.ts` | `test/jobs.test.ts` | It says a job failed, never why the database was slow |
| A freeze that refuses writes and keeps reads | A live breach draining money while the operator investigates — and a self-destruct that would rob the sellers instead | One row, checked before CSRF and authentication; the books, the audit log and every balance stay readable | `src/server/lib/lockdown.ts` | `test/lockdown.test.ts` | Two seconds of cache means it is immediate in practice, not instantaneous; and it does nothing about an attacker who already has the database file |
| Image metadata stripped before encryption | A photograph telling its recipient where it was taken, on what device, and when | Container metadata (EXIF, XMP, IPTC, timestamps, thumbnails) is removed on the sender's device; it reduces exposure and is not anonymity | `src/shared/media.ts` | `test/uploads.test.ts` | A format it cannot parse passes through unchanged, deliberately: a corrupted file is the worse failure |
| An upload allowance charged in bytes | One account turning the operator's disk into rows inside the request limit | Per-account byte budget over the same daily-rotating HMAC buckets, with no link between an account and a blob | `src/server/lib/rate_limit.ts` | `test/limits.test.ts` | It bounds the rate, not the total: blobs still accumulate until they expire (roadmap OPS-5) |
| A cost audit that fails the push | A hosted service quietly becoming mandatory, taking users' metadata with it | Dependencies, code and configuration are checked for anything that bills or phones home | `scripts/audit.mjs` | `test/audit.test.ts` | Name-based: a service reached through a variable this grep cannot see would pass, which is what review is for |
| A canary signed off the machine, published with its age | An operator compelled to hand over data or keys, and forbidden from saying so | Silence becomes visible: the dates are inside the signature, so this server can publish a statement or fail to, and cannot forge a fresh one | `src/server/lib/canary.ts` | `test/canary.test.ts` | It proves nothing when it is refreshed — an operator can be compelled to keep signing — and it depends on people noticing an old date. | No fingerprinting surface in the client | A page that identifies its own visitor through canvas, WebGL, audio, screen size, plugins or time zone | Those APIs are absent from `src/client` and `src/shared`, and a lint rule fails the build when one appears | `scripts/lint.mjs` | `test/fingerprint.test.ts` | It is a rule about this client only. | The query string is dropped on load | A campaign or click identifier arriving on a shared link and living on in the address bar, the history and the next copy-paste | This client reads no query parameter (asserted by test), so the whole query can be removed with `replaceState` | `src/client/urls.ts` | `test/fingerprint.test.ts` | It cannot un-send the request that already carried the parameter here, and it does nothing about an identifier hidden in the fragment, which the server never sees anyway |
